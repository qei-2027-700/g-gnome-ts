# 機内フレームを原作画像と照合する

このフォルダから `../../..` がリポジトリのルート。機種の寸法・残弾・IFF・マスク座標は書かない。`renderer.ts`、`vehicles.ts`、`weapons.ts`、他機種の機内ファイル全体は開かない。

## 写す範囲

写真をマスクしている `src/game/presentation/*-cockpit.ts` を1つだけ開き、次の対応行だけ写す。

- `src/game/presentation/<kind>-cockpit.ts`。viewBox は画像の画素サイズ。窓はマスクで黒のまま残す。計器の井戸だけ、マスクのあと `#000` で塗り戻す。
- `src/<kind>-cockpit.css`。その機種のクラスだけで枠と計器の割合を置く。新しいシェルは全体で `display:none`、その機種のときだけ表示する。
- `src/main.ts`。CSSと関数のimport、`#cockpit` への挿入、搭乗中だけクラスを付ける、画像の縦横比で幅と高さを置く、`?previewVehicle=<kind>` で既存任務を複製して最初から搭乗する。任務定義は増やさない。写真のIFFを複製した任務のIFFにしない。
- 他機種がシェルを隠しているセレクタ。既存の `*-shell` を `rg` し、ヒットしたセレクタへ新しいclassを足す。ヒット行以外は読まない。
- その機種の既存テストへ、シェルが実行時画像を参照することと、写真のIFF数字を含まないことだけ足す。パス座標は断言しない。新しいテストファイルは作らない。
- `docs/gameplay/cockpit-hud.md`、その機体のREADME、`assets/README.md` へ短い追記。

共通の武器行、残弾、充填、IFF、ホログラム、レーダー、照準、コンパスは、今あるDOMの位置だけ合わせる。写真の残弾・IFF・地形・ホログラム・レーダー・人物は初期値にしない。

## 窓を数値で決める

参照画像を開き、窓・計器・残す金属を見分ける。座標は次の出力を使い、画像の説明から画素を推測しない。計測結果と画面が食い違う場合は、該当箇所を再計測する。

```sh
node .agents/skills/gnome-cockpit/scripts/measure-frame.mjs assets/cockpits/<file>.png
```

各マスは `r,g,b`。接頭辞 `g` は写真の緑の地形、`s` は空、`h` は明るい計器の緑、`k` は黒。接頭辞の無い茶や灰色は数値のまま読む。支柱の茶を地形と判断して、この分類を直さない。

写真に地形や空が写る範囲は、中央も左右も最初のマスクで窓にする。窓は塗り戻さない。ゲーム状態から更新する計器の井戸は塗り戻す。武器の数字、IFF、ホログラム、中央下のレーダーを置く面を含む。皿、木目、無地の面は、その計器が無い理由にしない。台の外枠、支柱、リブの壁、飾りは残す。窓を横切る写真の配線は穴に含める。ブラウザの枠や黒帯は枠に入れない。`.radar-instrument` をその機種で隠して完成にしない。規則は[コックピット表示仕様](../../../docs/gameplay/cockpit-hud.md)の「写真の計器を固定表示にしない」。

## スタイルで再発させない

- `style.css` の `[hidden]{display:none}` は詳細度 `(1,1,0)`。同じかそれより後の `.機種 #id{display:flex}` が勝って、空の計器が出る。表示は `#id:not([hidden])` に付ける。
- `.throttle-meter` の `display` は変えない。停止中は空の枠にする。写真で塗りつぶされたバーは、移動中の状態であり静止画として置かない。
- `#cockpit` は `pointer-events:none`。押せる制御だけ `pointer-events:auto`。
- 照準とコンパスは `#flightHud` にあり、窓の穴から見える。`#world` は機内と同じ矩形にする。

## 原作と同じ画面比率で照合する

開発サーバーが5173にあればそれを使う。無ければスクリプトが起動し、自分で起動したものだけ止める。

```sh
node .agents/skills/gnome-cockpit/scripts/preview-shot.mjs <previewVehicle>
```

出力は `.artifacts/cockpit/<previewVehicle>/preview.png`。機種のクラスが `<previewVehicle>-cockpit` と違うときだけ、第2引数でクラス名を渡す。

原作画像とプレビューを同じ表示比率で並べ、窓の外形、支柱、ダッシュボード、計器の位置と大きさを順に比べる。画面比率が違う場合は位置ずれと切り抜きずれを混同しない。写真の地形が窓に残る、必要な枠が欠ける、計器が金属部分に重なるなど、主要な差があれば該当箇所を直して撮り直す。修正前後の画像を別名で残し、回数だけを理由に照合を打ち切らない。原作画像で判別できない境界は推測で確定せず、残る差として記録する。

確認するのは、搭乗で枠が出ること、窓に今の戦場が出ること、写真の残弾とIFFが残っていないこと、レーダーが写真の画素ではなく `.radar-instrument` で出ていること、降機と外部視点で枠が消えること、他機種にスタイルが残らないこと。出力の `radar` が `none` または `missing` のときは未完了で、皿が見えないことを理由に終わらない。射撃で弾道をずらさない。

関連する既存テストだけ実行する。テストの成功だけで枠と計器の位置が合ったとは判断しない。全体テストと `tsc` はCIに任せる。
