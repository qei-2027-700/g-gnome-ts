# G-Nomeのゲーム動作を変更する

このスキルの配置先から `../../..` がG-Nomeのルート。基本方針は [AGENTS.md](../../../AGENTS.md) に従う。

## 変更の境界を決める

ユーザーの自然文を、開始状態・操作または接触・結果の3点へ整理する。現行コードと該当仕様を読み、未実装なのか、既存処理の条件や見せ方が不足しているのかを判断する。必要な機能が既にあれば、重複実装せず、依頼された一連の操作で確認する。

| 対象 | 読む場所 |
| --- | --- |
| 移動・乗降・無人化・接触 | `src/game/simulation/simulation.ts`、`infantry.ts`、`parts.ts`、[歩兵仕様](../../../docs/gameplay/infantry.md) |
| 入力・停止・センター・全開 | `src/game/input.ts`、`settings.ts`、[キー仕様](../../../docs/technical/keybindings.md) |
| 武器性能・任務による差 | `src/game/content/weapons.ts`、`vehicles.ts`、`missions/` と対応する仕様 |
| 操作音声 | `src/main.ts` のイベント接続、`src/game/presentation/audio.ts`、[音声方針](../../../docs/audio/mission-controls-and-audio.md) |

パス表記はルートからの相対パス。対象の関数と、その状態を変更する呼び出し元を必要な範囲で追う。

## 状態とイベントを揃える

1. 乗降・無人化では、車体の向きと上半身の向きを区別する。センター復帰は車体を世界座標のゼロ方向へ回すことではない。移動・上下照準・追尾・出力の初期化と、損傷・残弾・エネルギーの引き継ぎは最新の仕様に合わせる。
2. 接触では、機体と歩兵の移動区間、高さ、有人・無人、生存状態を扱う。IFFによる敵味方の識別と物理的な接触条件を混同しない。高速通過をフレーム末尾の距離だけで判定しない。
3. 入力では、短押し・長押し・キーを離した後の維持・解除条件を区別する。通常移動と全開の最高速度、伏せと射出中の扱いを確認し、操作感の調整を未指定の性能倍率へ置き換えない。
4. 音声はシミュレーションの受理イベントから接続する。毎フレームの発声を避け、操作の再入力と状態変化のどちらで再生するかを仕様に合わせる。自動的な姿勢復帰と、ユーザーのセンター操作は別のきっかけとして扱う。

## 操作から検証する

該当する条件だけを選び、実操作に相当するテストを追加する。例えば、GASHR着弾→敵パイロット排出→徒歩接近→自動搭乗→操縦までを通す。内部関数の直接呼び出しだけでは、入力やフレーム更新との接続を確認した扱いにしない。

接触の変更では通過・高さによる非接触、入力の変更では解除・競合・長押し、状態遷移の変更では引き継ぎとイベントの一回性を選んで確認する。意図的に速度を変えた場合は、既存テストの移動時間も新仕様に合わせる。

[AGENTS.mdの検証方針](../../../AGENTS.md#検証)に従い、調整中は変更した処理と影響先のテストを実行する。共通処理の変更と、コード変更を含むコミット前は全体テスト・ビルドを確認する。対象コードが同じ状態で成功済みなら、その結果を再利用する。

結果は `.artifacts/` に保存し、関連仕様を更新する。回帰テストは既存の責務別ファイルへの追加・更新を基本とする。実ブラウザで確認していない操作感・見た目・発声は未確認と報告する。
