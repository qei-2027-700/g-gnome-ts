# G-Nomeのミッションを追加・変更する

基本方針は[AGENTS.md](../../../AGENTS.md)、定義の追加手順は[コンテンツ拡張手順](../../../docs/technical/content-extension.md)、任務と共通仕様の境界は[ミッションの追加と共通仕様](../../../docs/technical/mission-definitions.md)に従う。性能値、機種の一覧、達成条件の型、個別任務の仕様はこのスキルへ複製しない。達成条件の型は[types.ts](../../../src/game/content/missions/types.ts)の`Objective`、登録済み任務は[index.ts](../../../src/game/content/missions/index.ts)、機種は[vehicles.ts](../../../src/game/content/vehicles.ts)の`VehicleKind`。

外観は[gnome-vehicle-visuals](../gnome-vehicle-visuals/SKILL.md)、機内は[gnome-cockpit](../gnome-cockpit/SKILL.md)、武器は[gnome-weapon-tuning](../gnome-weapon-tuning/SKILL.md)、BGMは[gnome-bgm-import](../gnome-bgm-import/SKILL.md)、操作や乗降は[gnome-gameplay-change](../gnome-gameplay-change/SKILL.md)。地図から任務を作るときは、それらを開かない。

## 新しい任務を作る順

1. 範囲を固定する。入力は任務番号、根拠の地図、開始位置と向き、勝敗の言葉、地図上の機体と建物の関係。勝敗が`Objective`に入らないときは、地形を置く前に不足している型を伝えて止まる。
2. 近い既存の`mission-<番号>.ts`を読む。達成条件は`Objective`、登録済み任務は`index.ts`を見る。`mission-definitions.md`は境界の説明として読む。
3. 原作画像がある場合は、[任務地図とウェイポイント](../../../docs/gameplay/mission-map-and-waypoints.md#原作画像からフィールドまでの対応手順)に従い、元画像・切り出し範囲・画素上の目印と色領域の境界・各領域の地形と通行可否・方位の根拠・画素から任務座標への変換を任務資料に残す。色の明暗だけで平地と通行できない山・斜面を決めない。画像で確認できないものは補わない。縮尺のない画像では任務内で一つの仮の縮尺を使い、メートルを仮値と書く。
4. 読み取った平地・通行できない山や斜面・川・通路・橋・施設・開始位置を任務定義へ置く。尾根を軸に沿った矩形の崖にする場合は原形との差を残す。色領域の形を既存の地形型で表せない場合は必要な共通の地形表現と判定を追加する。機体と建物の代用はコンテンツ拡張手順の「Missionの追加」に従い、代用した対応を任務資料に残す。
5. 斜面・崖は、3Dメッシュが地面に接する輪郭と通行判定の輪郭を同じ座標で照合する。背景の山など衝突判定のない地形はプレイ可能領域へ重ねない。矩形の衝突判定に別形状のメッシュを使う場合は、接地面が同じ矩形になるよう作り、境界の外側から内側へ移動して止まる位置を描画寸法とともにテストする。この照合が済むまで、フィールド完成と報告しない。
6. 勝敗を既存の`Objective`へつなぐ。依頼が名指ししていない任意項目は、同じ手順に従って省く。
7. `missions/index.ts`へ登録する。`validateMissions`と、開始位置の関係から勝敗まで進む既存のミッションテストを足す。新しいテストファイルは作らない。崖・川・建物を多く置くときは[密集した障害物と更新コスト](../../../docs/technical/simulation-cost.md)に従い、警戒が始まる前後で1ティックが止まらないことを確認する。原作画像と座標から描く地図、実ブラウザの3D表示で色領域の境界を照合し、平地の通行と山・斜面への進入不可、遮蔽・攻略経路を確認する。未一致を任務資料に残し、画像を貼っただけで一致と扱わない。実ブラウザで確認した表示・操作と、自動テストだけを分けて報告する。

## 既存任務の配置を変えるとき

変える任務の定義、任務資料、必要なテストだけを更新する。配置・地形・開始位置・橋・施設は「原作画像からフィールドまでの対応手順」に従い、確認した関係を既存のミッションテストで固定する。すでに入っているずれを後から直すときは[gnome-mission-map-match](../gnome-mission-map-match/SKILL.md)。頼まれていない任務の地図は直さない。

任務IDや個別の機体IDによる分岐を共通処理へ追加しない。
