# G-Nomeのミッションを追加・変更する

基本方針は[AGENTS.md](../../../AGENTS.md)、定義の追加手順は[コンテンツ拡張手順](../../../docs/technical/content-extension.md)、任務と共通仕様の境界は[ミッションの追加と共通仕様](../../../docs/technical/mission-definitions.md)に従う。性能値や個別任務の仕様はこのスキルへ複製しない。

## 依頼を任務定義に落とす

対象の[任務資料](../../../docs/missions/)と近い既存ミッションを読み、確認済みの原作情報、ユーザー指定、試作の仮値を分ける。開始状態、配置、進行条件、成功・失敗条件を確認する。必要な目標が[既存の型](../../../src/game/content/missions/types.ts)と[進行処理](../../../src/game/simulation/simulation.ts)で表現できるか判断する。

既存の機体・施設・目標タイプで表現できる場合、新しい任務定義を `src/game/content/missions/mission-<番号>.ts` に作り、`missions/index.ts` へ登録する。配置・地形・目標・任務限定の上書きは定義に置き、機体や武器の共通性能へ混ぜない。既存ミッションの変更では、その定義と必要な資料・テストを更新する。

新しい目標タイプ、操作、AI、描画、音声の挙動が必要な場合は、対応する責務のコードとテストも変更する。任務IDや個別の機体IDによる分岐を共通処理へ追加しない。操作や乗降を変更する場合は `gnome-gameplay-change`、画像資料に基づく機体の見た目を変更する場合は `gnome-vehicle-visuals`、BGM音源を取得・接続する場合は `gnome-bgm-import` も適用する。

## 登録から進行まで検証する

型と `validateMissions(MISSIONS)` で必須項目・重複・参照IDを確認する。既存の責務別テストへ、開始状態から実際の操作・時間進行を経て目標が達成または失敗する経路を追加する。配置や地形を変えた場合は、到達経路、衝突、射線、施設の進入位置など変更に関係する条件を確かめる。表示を変えた場合は選択画面、地図、目標表示の関連テストを選ぶ。

型と参照検証だけで攻略可能性は保証されない。実ブラウザで確認した表示・操作・音声と、自動テストのみで確認した内容を区別して報告する。任務資料には出典、仮値、未確認箇所を残す。
