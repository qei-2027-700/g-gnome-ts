# 原作画像と現行モデルを突き合わせる

このフォルダから `../../..` がリポジトリのルート。保存先、命中、砲口、資料の書き方は [gnome-vehicle-visuals](../gnome-vehicle-visuals/SKILL.md) と [外観手順](../gnome-vehicle-visuals/references/exterior.md)。このスキルは突き合わせの順番だけを持つ。機内・HUD・性能・武器は対象にしない。

## 先に差を固定する

1. 機種IDを一つ決め、原作画像と機種資料を確認する。画像の外観・機内・ホログラムと撮影方向を分け、ファイル名だけで内容を判断しない。
2. 現行モデルの画像が無ければ、原作画像と対応する方向を修正前に描画する。確認できない方向は未確認のままにする。
3. 目立つ差から順に「部位 / 原作 / 現行」を記録する。ユーザーが指定した範囲を優先し、見えない背面・内部・模様は足さない。ホログラムの緑・黄・赤は塗装にしない。
4. 胴体幅を基準に、頭・肩・腰の高さ、張り出し、脚や砲の太さを画像上の比率で比べる。透視や姿勢による見かけの差と、形状そのものの差を分ける。

## その差だけ実装する

- 寸法・配置の差はその機種の `shape` から直し、描画、命中、砲口への影響を確認する。装飾や配色の差は描画側で直す。
- `renderer.ts` は対象機種の分岐と共有処理の必要な箇所を読む。無関係な機種には変更を広げない。
- 姿勢の差が見えた場合は、関節長・角度と停止時の姿勢も確認する。歩行中の一枚を停止姿勢の根拠にしない。
- 参照画像に無い蓋、開口、装甲は足さない。

## 同じ方向で描いて終える

原作と現行モデルを同じ方向・近い画角で比べる。現行画像が提供されていれば修正前の再描画は省ける。比較用の描画はラベルを付けて保存する。

```sh
GNOME_MODEL_LABEL=before node .agents/skills/gnome-model-match/scripts/render-views.mjs <kind> front
```

方向は `front` `side` `rear` `top` で、必要なものだけ渡す。修正後は `GNOME_MODEL_LABEL=after` などで別名保存する。出力は `.artifacts/model-match/<kind>/`。既定では空きポートを選び、必要なら `GNOME_MODEL_PORT` で指定する。確認用HTMLはスクリプトが消す。描画できない場合は原因を確認し、構造テストと描画確認の結果を分けて伝える。

描き比べて根拠のある差を直し、同じ方向で再確認する。回数では打ち切らず、指定された外観の主要な差が解消したところで終える。画像から判断できない箇所や、追加の修正で改善の根拠が得られない箇所は推測で埋めず、残る差を報告する。

## 確認

変更した寸法・姿勢・描画の影響先を調べ、必要な既存テストを実行する。古いシルエットを前提にした断言は、新しい `shape` に合わせて更新する。構造テストの成功を外観一致の証拠にしない。

機体READMEに、合わせた特徴と試作のままの数値を短く残す。機種の寸法や性能値をこのスキルへ書かない。
