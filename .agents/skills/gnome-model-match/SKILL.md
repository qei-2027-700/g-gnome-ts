# 原作画像と現行モデルを突き合わせる

このフォルダから `../../..` がリポジトリのルート。保存先、命中、砲口、資料の書き方は [gnome-vehicle-visuals](../gnome-vehicle-visuals/SKILL.md) と [外観手順](../gnome-vehicle-visuals/references/exterior.md)。このスキルは突き合わせの順番だけを持つ。機内・HUD・性能・武器は対象にしない。

## 先に差を固定する

1. 機種IDを一つ決める。ユーザーの画像、その機種の `docs/reference/vehicles/`、`src/game/content/vehicles.ts` の該当定義だけを見る。`renderer.ts` 全体、武器表、任務配置は開かない。
2. 原作画像と、ユーザーが付けた現行モデルを開く。ファイル名で内容を判断しない。添付が無い画像は未確認のままにする。
3. 差を5項目以内で書く。各項目は「部位 / 原作 / 現行」。ユーザーが述べた差が作業範囲で、見えない背面・内部・模様は足さない。ホログラムの緑・黄・赤は塗装にしない。
4. 胴体幅を1として、付く高さ（頭・肩・腰）、左右への張り出し、脚や砲の太さを比率で書く。メートルを先に置いて描き直さない。

## その差だけ実装する

- その機種の `shape` を先に変える。描画、命中、砲口は同じ `shape` を使う。
- `renderer.ts` はその kind の分岐だけを読む。他機種の分岐は読まない。
- 歩行の関節長は、姿勢の差を頼まれたときだけ変える。
- 参照画像に無い蓋、開口、装甲は足さない。

## 同じ方向で描いて終える

ユーザーの現行画像があるときは、修正前の描画をしない。修正後は、原作と同じ方向だけ描く。

```sh
node .agents/skills/gnome-model-match/scripts/render-views.mjs <kind> front
```

方向は `front` `side` `rear` `top` で、必要なものだけ渡す。出力は `.artifacts/model-match/<kind>/`。確認用HTMLはスクリプトが消す。Chrome か開発サーバーが無いときは、構造テストの結果と、描画できなかったことを分けて伝える。

描き比べて残った差だけを直す。2回目の描画のあとまだ違えば、その差を報告して止める。推測で3周しない。

## 確認

その機種名が出る既存テストだけ実行する。新しいテストファイルは作らない。古いシルエットを前提にした断言は、新しい `shape` に合わせて更新する。

機体READMEに、合わせた特徴と試作のままの数値を短く残す。機種の寸法や性能値をこのスキルへ書かない。
