# 資料から機内ビューと外観を再現する

このスキルの配置先から`../../..`がG-Nomeのルート。[AGENTS.md](../../../AGENTS.md)に従う。既存の同機種を調整する場合も、新しい機種・施設を加える場合も使う。

## 対象と資料を対応づける

ユーザーの呼び方と既存の機種ID・勢力・用途を照合し、対象を絞る。[機体資料の目次](../../../docs/reference/vehicles/README.md)、対象の資料、実装を必要な範囲で読む。同名の塔でも勢力が違えば同じ外観と決めない。

画像は実ファイルを開いて確認し、ファイル名だけで内容を判断しない。資料が複数ある場合は、各画像の「機内／外観／HUD／地図／発射・歩行中」と撮影方向を分けて対応づける。1枚に写る窓外の機体、自機ホログラム、目標ホログラム、人物像はそれぞれ別の対象になり得る。

新しい指定が既存資料と違う場合はユーザー指定を優先する。資料同士の違いは、視点・勢力・損傷・動作状態・任務の違いで説明できるか確認する。結果を左右する不明点だけ質問し、独立して進められる部分は実装する。未添付の画像を確認済みと扱わない。

## 再現する部分を選ぶ

- **機内ビュー・照準・計器**：[機内ビューの手順](references/cockpit.md)を読む。
- **外観モデル・ホログラム・脚や砲塔の動き**：[外観と動きの手順](references/exterior.md)を読む。
- **両方**：共通の機種IDを確定してから、必要な手順を併用する。外部視点への切り替えも確認する。

見えた輪郭・色・配置と、試作で補う形状・数値を区別する。ホログラムの緑・黄・赤は損傷表示であり、塗装色の根拠にしない。白黒資料から色を確定せず、一方向の画像から背面・内部を確定しない。見た目の調整で最高速度・武器性能を変更しない。操作や性能も指定された場合は[ゲーム動作のスキル](../gnome-gameplay-change/SKILL.md)を併用する。

## 保存先と接続先

以下はリポジトリのルートからの相対パス。既存の構成と機種IDを使い、対応する機体のファイルを先に探す。

| 対象 | 配置・接続先 |
| --- | --- |
| 原作の観察資料、根拠画像、確認済み・未確認の記録 | `docs/reference/vehicles/<既存の機種フォルダ>/`。既存画像は移動・複製せず参照する |
| 実行時に使う機内画像 | `assets/cockpits/`。観察資料だけの画像を実行時コードから直接読み込まない |
| 機内フレーム・機種別HUD形状 | `src/game/presentation/*-cockpit.ts`、`src/*-cockpit.css`、`src/main.ts`の選択・接続 |
| 機種の識別と共有寸法 | `src/game/content/vehicles.ts`、`vehicle-shapes.ts` |
| 外観・部位・動き・ホログラム | `src/game/presentation/renderer.ts`、`locomotion.ts`、`hologram.ts` |
| 形状に対応する命中領域・砲口 | `src/game/simulation/parts.ts`、既存の発射位置計算 |
| 現在の表示仕様と素材索引 | `docs/gameplay/cockpit-hud.md`、`assets/README.md`、`docs/reference/vehicles/README.md`の該当箇所 |
| スクリーンショット・ログ・一時的な確認画面 | Git対象外の`.artifacts/<作業名>/` |

新規の保存先は用途に合わせて選ぶ。施設の機内も既存の施設表示の構成を調べて接続する。機内を作るためだけに移動可能な機体として登録しない。過去の参照画像を一括整理したり、無関係なファイルを改名したりしない。

## 検証と完了

[プロジェクトの検証方針](../../../AGENTS.md#検証)に従い、変更が壊し得る表示・状態・命中位置を確認する。配色・装飾は実画面、共有寸法・部位・更新処理は関連テストも確認し、必要な範囲でビルド・全体テストを行う。ゲームコードを変更しない資料整理だけならゲームの検証を増やさない。

実ブラウザの確認には利用可能な`evid-verify`を使い、対象の状態が分かる画面と検証記録を保存する。NullEngineでの構造確認、実ブラウザでのGPU描画、実操作での確認を区別する。一時的な確認画面を使った場合は本編で確認した範囲と分けて記録する。

機体資料には根拠へのリンク、反映した特徴、補った部分、残る未確認箇所を短く残す。元資料や性能表をスキルへ複製しない。新規素材・機種・資料を加えた場合は該当する索引を更新する。最終回答は変更点、確認結果、確認画像、未確認の重要な点を簡潔に伝える。
