# 機内ビュー・HUDの再現

元の画像に写る金属フレーム、窓、照準、計器を別々に扱う。専用の既存実装があれば拡張し、共通HUDを機種ごとに重複実装しない。仕様の参照先は[機内・HUD仕様](../../../../docs/gameplay/cockpit-hud.md)。以下のパスはリポジトリのルート基準。

## 画像を表示用の要素へ分ける

画像の縦横比と、ゲーム画面が写る範囲を確認する。スクリーンショット全体の余白・黒帯・ブラウザ枠を操縦席の形状へ取り込まない。比率を保つ描画では、実際の表示領域を基準に位置を合わせる。

| 要素 | 実装での扱い |
| --- | --- |
| 金属フレーム、支柱、固定のパネル | 実行時画像とSVGマスク、または既存のSVG・CSSで再現 |
| 窓外の地形・敵・爆発 | 元画像では隠し、現在の3D戦場を表示 |
| 照準・目盛り・IFF・残弾・充填・損傷 | 元画像の表示を隠し、実際のゲーム状態から更新 |
| 自機・目標のホログラム、人物・名前 | 対応する機種・選択状態・人物の表示へ接続 |

画像に写る残弾、IFF、人物、ロック状態を初期値や固定装飾として使わない。複数画像に同じ枠がある場合は、枠の基準画像と、照準・計器・発射状態の追加資料を分けて利用する。

既存の画像をコード上でマスク・合成できる場合は、その構造を使う。ラスタ素材の生成・加工が必要なら、利用可能な画像制作のスキルとツールを選ぶ。資料にない内部を補う場合は仮の再現と記録する。

## フレームと計器を接続する

1. `assets/cockpits/`の実行時素材を`src/game/presentation/*-cockpit.ts`から参照し、窓と元の表示値を除くマスクを作る。既存画像を使う場合は新しいコピーを増やさない。
2. 機種別CSSで枠・計器の比率と配置を合わせる。照準、ホログラム、レーダー、残弾などは既存の更新処理へ接続する。
3. `main.ts`の機種選択、素材の挿入、CSS読み込みを確認する。専用フレームが実際の搭乗ルートで選ばれるところまで実装する。

寸法は画像の座標系と実際の表示領域を対応させる。画像のピクセル座標を別の縦横比の画面へそのまま当てはめない。CSSは機種で限定し、他の操縦席へ色・位置・表示状態を漏らさない。

照準の色・輪郭は通常、照準一致、ロック、距離表示を併せて確認する。共通のロック用CSSが専用色を上書きしていないか、実際の表示色まで見る。レーダーは固定台座と可動砲塔のどちらを基準にするか既存仕様を確認する。

発射中の光が写る場合は、静的なフレームに焼き込まず発射イベントの演出にする。機内で見える噴射の位置と、外部の砲口・弾道・命中判定を区別する。参考画像に合わせるために弾道をずらさない。

## 機内に固有の確認

- 搭乗・同乗で対応する操縦席が表示され、降機・C/Zの外部視点・VISOM・任務終了演出で適切に解除される。
- 窓に現在の戦場が映り、元画像の敵・地形・人物・残弾が残っていない。窓以外が透けていない。
- 縦横比の異なる画面でも枠・照準・計器の位置が合い、操作ボタンを覆わない。
- 射撃、充填、目標変更、損傷で実際の計器が更新される。他機種へ乗り換えると専用スタイルが残らない。
- 揺れ・発射光も指定された場合は、移動・停止・一時停止に追従し、照準方向まで意図せず動かさない。

全項目を毎回テストへ追加する必要はない。変更した表示と、その状態を切り替える操作を選んで確認する。
