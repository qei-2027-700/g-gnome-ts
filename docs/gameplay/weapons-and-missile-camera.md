# 武器の分類・表示とミサイル専用カメラ

- 作品：G-Nome再現
- 媒体：Babylon.jsによるPC向けブラウザゲーム
- 対象：武器の分類、弾の見た目、弾薬・エネルギー、誘導中の視点
- 状態：分類と色、通常ミサイルの限定的な自動追尾はユーザー指定。VISOMの手動誘導・固定速度・専用視点と、3-3検証版での敵ASV誘引を実装。原作のカメラ構図・詳細性能は照合中
- 記録日：2026-10-22
- 関連：[機体・武器の数値調査](../reference/vehicles-and-weapons.md)、[カメラ・機内表示](cameras-and-cockpits.md)、[実装計画](../technical/implementation-plan.md)

## ユーザーが挙げた4分類

| 分類 | ユーザーの説明 | 再現時に管理すること |
| --- | --- | --- |
| レーザー系 | 弾数制限がない武器 | エネルギー消費、充填、弾の色・形・速度、発射可能条件 |
| マシンガン系 | 赤い弾で表現される武器 | 弾数、連射、砲門数、赤い弾の軌跡・着弾、発射音 |
| ミサイル系 | ミサイル | 弾数、弾速、誘導方式、煙・軌跡、爆風、カメラの切り替え |
| ミーゾンタワー系レーザー | 青で表現される武器 | 青い弾の見た目、対盾・対装甲威力、充填、発射元の施設・機体 |

この4分類を仕様整理の入口にする。ただし弾の色だけでダメージや弾薬方式を決めず、個別武器の資料で照合する。「弾数制限なし」は連射し放題という意味ではなく、エネルギーと充填の制限を別に扱う。

ミーゾンタワー系を通常のレーザー系の下位分類にするか、独立した表示分類にするかはデータ設計時に決める。機体にも同系統の武器が存在し得るため、設置場所を武器の仕組みと同一視しない。GASHR・EGGERなどの特殊武器を無理に4分類へ当てはめない。

命中時の目標選択は、[自動目標選択の共通仕様](cockpit-hud.md#命中時の自動目標選択共通仕様2026-10-30)に従う。未選択なら生存している命中対象を必ず自動選択し、選択済みなら現在の目標を維持する。武器の種類で条件を変えない。

## 全機体共通のレーザー充填（2026-10-23）

ユーザー指定として、走行中はレーザーの充填が遅くなる。未充填でも発射できるが、充填量が少ないほど届く距離が短くなる。満充填時の射程と充填の特性は機体・武器ごとに管理し、この規則を全機体に適用する。

試作ではFIL-30とRAIDを共通処理に接続した。移動は実際の座標変化で判定し、前進・後退・惰性走行・敵AIの移動を含める。未充填発射でもエネルギーを消費し、ゲージは空になる。レーザーの到達距離に、発射直前の充填量を反映する。発射間隔と満充填までの時間は別の設定項目にする。

ユーザー指定により、搭乗中の機体でレーザーを発射し、その充填が満タンへ戻ったときに、女性ボイス2（`solemn`）で「Ready」と案内する。攻撃後の充填回復ごとに1回だけ発声し、開始時の満充填や、満タンのままのフレーム更新では繰り返さない。移動による充填の遅れを反映し、降機中に満タンへ戻った機体への再搭乗では遅れて発声しない。発射間隔がまだ残っていても、案内は充填が満タンになった時点で行う。

仮値はFIL-30の最大射程220m・最小22m・停止時充填0.55秒、RAIDの最大180m・最小18m・停止時0.7秒。走行中の回復速度は停止時の50%、射程は充填率に対して直線的に変化する。これらの数値・曲線は原作での測定結果ではない。今後の機体は搭載レーザーとその設定を登録して同じ処理を使う。レーザー以外の武器へ充填の規則は適用しない。

ユーザー指定により、レーザーは連射と着弾の両方を遅くした。即時命中から飛翔弾へ変更し、衝突時にダメージを与える。ミサイルは飛翔速度を約10%上げ、従来の最大到達距離を維持した。現在の調整値と任務限定の例外は[ミッションの追加と共通仕様](../technical/mission-definitions.md#今回の戦闘調整)を参照する。

## データの分け方

| 項目 | 定義するもの |
| --- | --- |
| 武器分類 | レーザー、マシンガン、ミサイル、ミーゾン系、特殊武器など |
| 消費資源 | 有限弾数、消費エネルギー、充填時間。武器ごとに指定 |
| 弾の表示 | 色、形状、発光、軌跡、煙、着弾エフェクト |
| 弾の挙動 | 速度、寿命・射程、直進、追尾、プレイヤーによる誘導 |
| ダメージ | シールド、装甲、歩兵、爆風に対する作用 |
| カメラと操作 | 機体から操作するか、ミサイルカメラへ移って誘導するか |
| 音 | 発射、飛翔、着弾、爆発。表示分類だけに依存させない |

武器の描画、物理的な弾の移動、命中処理、音声を分離する。色を変更しても当たり判定・威力は変わらない構成にする。有限弾数、エネルギー不足、充填量について、表示と実際の発射可否・射程を一致させる。

## 通常ミサイルの自動追尾（2026-10-24）

ユーザー指定により、通常ミサイルは目標へある程度追尾する。SREM・UNKPA・TCROCK・CHUM・HSSO・SAG5Tに適用する。プレイヤーは選択目標、AIは実際の攻撃対象を発射時に記憶し、その位置へ飛行方向を少しずつ変える。Tによる機体の追尾照準とは別で、発射後に選択を解除・変更しても元の目標を追う。目標未選択では照準方向へ直進する。

旋回速度には上限を設け、弾速・寿命・威力・残弾消費は変更しない。発射方向から30度以内の目標を捕捉し、飛行方向から45度を超えた場合や目標が破壊された場合は追尾を失い、その後は直進する。別の目標へ自動で乗り換えない。旋回速度0.45rad/sとこれらの角度は原作の測定値ではなく、「ある程度追尾する」を実装するための仮値。設定元は`src/game/content/weapons.ts`の`MISSILE_HOMING`。ScorpロケットタワーのUNKPAだけは、ユーザー指定の調整として`VehicleSpec.missileHomingScale`に1.2倍を設定する。発射時の倍率を弾が保持し、通常・AIのそれぞれの追尾旋回速度へ適用する。初期残弾は30発。詳細は[ロケットタワーの仕様](../reference/vehicles/scorp-rocket-tower/README.md#武器2の追尾調整2026-10-30)を参照。

敵・味方AIのミサイルは命中精度を下げ、発射時の狙いへばらつきを加える。追尾にも同じ照準のずれを残し、毎フレーム目標の中心へ補正しない。通常は水平±0.035rad・垂直±0.018radの範囲、追尾の旋回速度0.18rad/s、目標位置の更新間隔0.35秒とする。

脱出して空中にいる人物に対しては、水平±0.14rad・垂直±0.09rad、追尾旋回0.045rad/s、位置更新0.75秒とし、上下・横移動へ追いつきにくくする。敵AI・味方AIに同じ制約を使い、プレイヤーとNPCの脱出兵を同じ基準で扱う。ばらつきは発射ごとに変わり、検証時には同じ条件から再現できる。値はユーザーの精度調整依頼に合わせた試作値で、`AI_MISSILE_ACCURACY`に置く。プレイヤーの射撃入力による照準・追尾、弾速・威力・寿命・弾数は維持する。無敵時間や命中の取り消しは加えず、実際に直撃した弾は通常どおり処理する。

VISOMは以下の手動誘導を維持し、自動追尾を適用しない。GASHRやTCREAPなど、ミサイル以外の飛翔弾にも適用しない。

## VISOMの手動誘導と呼称

ユーザーから「mission 3-3などで登場するバイソンミサイルには追尾機能があり、カメラが独特のビューになる」との説明があった。この名称と3-3での挙動はユーザーの情報として記録する。

その後、ユーザーがBYSOM表記で専用ビューの実装を依頼し、続けて「VISOMは手動誘導」「方向キーで方向を変える」「速度は一定」と説明した。実装の武器IDと表示は最新のVISOMへ揃える。過去の表記だけを根拠に、日本語版の正式な音声・綴りまで確認済みとは扱わない。

[保存マニュアル](../reference/manuals/G-Nome_Manual_Win_EN.pdf)の本文p.28では、VISOMはFly-by-wire AP Missile、射程1000mとされる。[参考ブログのVISOM解説](https://ameblo.jp/g-nome/entry-12450789611.html)では、カメラを見ながら方向キーで誘導し、誘導中は機体を操作できないと説明されている。

実装はプレイヤーがミサイルのカメラから方向を操作する方式とする。選択対象への自動追尾は行わず、対象が移動しても入力なしでは飛行方向を変えない。3-3検証版ではUnion ASVへVISOMを搭載するが、原作での任務固有の搭載数・武器枠は引き続き照合する。

## 実装したミサイルカメラの状態遷移

```text
機体のビュー
  → カメラ誘導ミサイル発射
    → ミサイルの専用ビューと誘導操作
      → 命中・地面衝突・射程到達・誘導終了
        → 機体の元のビューへ復帰
```

搭乗中の3種類のカメラとは別に、VISOM発射時にミサイル位置の専用視点へ切り替える。提供画像に合わせ、赤茶・グレーの筒状の光学フレームを専用表示する。中央の開口部には飛行中の3D映像を表示し、参考画像に写る固定の景色・ASV・画面右下の人物は重ねない。元の機体ビューの種類は保持し、復帰時に戻す。

方向キーまたはWASDで旋回・上下操作を行う。右ドラッグの照準入力もミサイルへ送る。旋回や上下操作では速度を変えず、Shiftでも加速しない。ユーザー指定により、発射時に機体を停止させず、誘導中も発射前の出力と車体の進行方向で移動を続ける。加減速・損傷による速度制限・機体や地形との接触判定は通常どおり適用する。誘導中の方向・上下入力はミサイルへ送り、機体の旋回・出力変更・追加の武器発射には使わない。視点を戻した後は機体の操作を再開する。

Spaceまたは画面の復帰ボタンで誘導を終了できる。この場合もミサイルを消去せず、最後の方向と速度で飛び続ける。機体ビューへ戻って移動・照準操作を再開しても、発射済みの弾には影響しない。復帰後に命中した場合も、通常の着弾処理でダメージを与え、3-3のVISOM命中回数へ加算する。命中、地面衝突、射程到達、操縦機体の破壊・降機では専用視点を解除する。ポーズ中は弾の位置と残り時間を止める。再挑戦・任務切り替えでは誘導状態と弾を初期化する。

現在の飛翔速度90m/s、旋回速度1.15rad/s、上下角の上限±1.15rad、視野角0.85rad、命中時のダメージ2は試作値。最大飛行距離1000mはマニュアル掲載の射程を参照した。対装甲と対シールドの個別威力、爆風、原作のカメラ構図と操作感の一致は未確認。コードの正本は `content/weapons.ts` と `simulation/guided-flight.ts`。

ユーザーの速度調整依頼により、VISOMは110m/sから90m/sへ減速した。速度は `src/game/content/weapons.ts` の `VISOM_SPEED` で指定し、飛行時間も同じ値から計算して最大飛行距離1000mを維持する。手動誘導中の速度一定という規則も維持する。

## 3-3の敵ASV誘引

ユーザー指定により、同じ敵ASVへVISOMが2発命中すると、その機体がプレイヤーへ接近する。任務の `lures` に対象ID、武器、必要命中数を記し、共通処理へ接続する。他の武器で攻撃されていなければ、VISOMの1発目では持ち場を維持して警戒・反撃し、2発目で誘引イベントを1回だけ発行する。

シールドに吸収された命中も数える。外れ、岩への着弾、別のASVへの命中、他の武器、敵側の発射、空の機体への命中は対象の誘引回数へ加えない。命中数は対象ごとに保持し、誘導を途中で終了した後の実際の着弾も反映する。再挑戦ではゼロへ戻す。

3-3の検証版では、誘引に加え、EGGERによる機内歩兵の排除と機体奪取、地雷の探知表示、仲間3人のScorp機搭乗による勝利判定を実装した。EGGERは徒歩時の武器2に特別装備する。正式な地形・配置・性能値・勝利条件との照合は継続する。[3-3の仕様](../missions/mission-3-3.md)を参照する。

## 初回1-1との関係

最初の1-1はUnion SentryのFIL30・FLECH、敵Merc SentryのRAID・CHUM、Merc Tactical DefenseのRAID・DASY・SAG5Tを照合する。原作での搭載確認がないVISOMを1-1へ追加しない。

基盤には武器別の誘導・描画・カメラを追加できる構成を用意し、VISOMの専用ビューそのものは該当ミッション・機体を再現する段階で実装する。


## 被弾した敵の反撃（2026-10-24）

3-3の誘引待ちが通常攻撃への反応まで止めていた不具合を修正した。機関銃・レーザー・通常ミサイル・歩兵銃で敵に命中すると、シールドだけで吸収された場合も警戒する。プレイヤーが攻撃した場合はプレイヤーへ、味方機が攻撃した場合はその攻撃元の機体へ接近・照準・反撃する。命中していない射撃では反応させない。反撃先が破壊・無人化されたら、その機体への追撃を解除する。

通常の被弾反応とVISOMの誘引回数は別に管理する。通常攻撃や味方の攻撃では誘引回数は増えず、VISOMの2発命中による目標達成には代用できない。味方に反撃している途中でも、プレイヤーのVISOMが同じ敵へ2発命中すれば、その敵はプレイヤーへ誘引される。武器の威力・残弾・速度は共通定義を維持する。


## 赤い菱形のレーザーと弾速の再調整（2026-10-24）

ユーザー提供の[レーザー参照画像](../reference/observations/mission-3-3/user-red-laser-2026-10-24.png)を確認した。白く光る芯を赤い菱形が包む飛翔弾として表示する。従来の細長い緑色の弾と、端点まで一瞬でつながる緑色の線は使わない。画像から弾速の数値は測定できないため、速度はユーザーの「もっとゆっくり」という指定に対する試作値とする。

最新の「もう少しだけ速度を上げたい」という指定に合わせ、レーザーのP2MEC・FIL-30・CETIは60m/sから72m/sへ調整した（試作値、20%増）。設定元は`src/game/content/weapons.ts`の`LASER_FLIGHT_SPEED`。100m先への到達に約1.4秒かかる。線状のRAIDとTCREAPは60m/sを維持する。プレイヤー・味方・敵が同じ武器定義を使い、当たり判定とダメージは飛翔弾が接触した時に処理する。最大射程を保つため、弾の寿命は射程を弾速で割って求める。威力・充填・発射間隔・エネルギー消費と、ミサイルの速度はこの調整では変更しない。

P2MECの描画はカメラ側を向く赤い四角形を菱形に見せ、中央へ小さい白い芯を重ねる。見た目の大きさは試作値。煙や長い尾は付けず、既存の地形・機体・歩兵への衝突判定を使う。


## TCREAPの赤い線状弾（共通仕様・2026-10-24）

ユーザーの最新指定により、TCREAPは細い赤い線が射出され、進行方向へ飛ぶ弾として描画する。菱形や白い芯は付けず、線をカメラへ正対させない。プレイヤー・味方・敵のすべてに適用する。弾速は試作値60m/sを維持し、`MACHINE_GUNS.TCREAP.projectileSpeed`で設定する。

今回の指定では表示形状を変更し、現在の残弾式と射撃性能を維持する。1発で残弾を1消費し、射程160m、威力3、発射間隔0.11秒、エネルギー消費なしの既存値を使う。プレイヤー・味方・敵に共通で、機体や歩兵へのダメージは接触後に与える。歩兵へ命中しても、ミサイルの即死判定ではなくTCREAPの威力を使う。弾薬式か充填式かなどの原作照合と、ユーザーによる見た目の指定は区別する。

## DASYとRAIDの共通の発射表現（確定仕様・2026-10-24）

ユーザー指定により、DASYは赤い弾を発射するマシンガン。銃口の発光と弾道を赤色で描く。RAIDは赤い細長いレーザーとし、菱形の弾では表現しない。プレイヤー・敵・味方で同じ武器の描画を共有し、任務によって色や弾の形を変えない。

DASYの連射と弾数消費、RAIDの飛翔・エネルギー消費・充填は既存の共通処理を使う。今回の指定では速度・威力・射程を変更しない。FIL-30はRAIDと同様の棒状の赤い弾を使い、TCREAPには上記の赤い線状弾を使う。


## 充填表示とMerc TacticalのRAID発射口（確定仕様・2026-10-24）

ユーザー指定により、レーザーを装備している機体の機内画面には充填ゲージを表示する。発射で空になり、現在の充填量に合わせて戻る。通常時は緑、充填中は黄色で表し、走行中の充填速度を反映する。レーザー枠の位置へゲージを置くため、Merc TacticalのRAIDは右上の武器3に表示する。外部視点や徒歩時には、その機体の機内ゲージを表示しない。

Merc Tactical Defense HAWCのRAIDは、コックピット直下の中央銃口から発射する。機体モデルに同じ位置の銃身を設け、プレイヤー・敵・味方とも、銃口を出発点として赤い発光と細長いレーザーを描く。機内カメラの位置から弾を発生させない。発射口の寸法・位置は試作値として`MERC_TACTICAL_RAID_MUZZLE`で共有する。照準先へ向けて飛ばし、速度・威力・射程・エネルギー消費は維持する。

## 長押し射撃と高速連射の制限（確定仕様・2026-10-24）

ユーザーの最新指定により、射撃キー・マウスを長押しして攻撃を続けられる。通常の長押し射撃は最短0.5秒間隔を試作値とし、武器本来の発射間隔が長ければそちらを優先する。通常の機体は弾数・エネルギーを消費し、弾切れやエネルギー不足では発射しない。ミーゾン・ガードタワーは[共通の外部給電仕様](../reference/vehicles/merc-meson-tower/README.md#射撃と給電の共通仕様2026-10-29)により、給電中は弾数・蓄積エネルギーの制限なく射撃できる。ボタンを離せば連射を止める。押し直しても武器本来の発射間隔は無視できない。

通常機体のレーザーは、長押しを続ける場合は充填完了も待つ。走行中は既存の充填速度の低下を反映する。単発の押し直しによる未充填発射と、充填量に応じた短い射程は維持する。Scorp Assault・Darken Tactical Defense・Merc Assault・Union Assault HAWCは例外とし、レーザーの長押しで充填完了や共通の0.5秒制限を待たず、武器本来の発射間隔で繰り返す。機銃・ミサイルにはこのレーザー用の例外を適用しない。 Merc Assault HAWCの実武装RUPPもこの例外に含め、1キーと左マウスの長押しで二門を繰り返し発射する。走行中の未充填状態でも継続し、入力を離すと止まる。RUPPの現在の1秒間隔は試作値として維持し、無制限の同時発射にはしない。

カスタムキーにも適用し、VISOM誘導中は従来どおり別の射撃を行わない。射撃キーを押したまま搭乗・降機した場合は、一度離してから新しい武器で発射する。0.5秒は長押し入力の繰り返し間隔であり、武器定義の速度・威力・射程を書き換えるものではない。設定元は`HELD_TRIGGER_INTERVAL`。

例外4機種のモデル・性能は現在の機体一覧に未登録。`LASER_HOLD_FIRE_HAWCS`へ機種IDを予約し、入力の例外を実装・検証している。Assaultを既存のSentryやScorp Tacticalへ読み替えず、Merc Tactical Defenseにも例外を適用しない。

## 遮蔽物・機体による防護（2026-10-24）

敵の機銃は、発射位置から射程内の最初の接触先を判定する。岩・建物・崖・固定設備の残骸、別の機体、歩兵が手前にある場合は、奥の狙った相手へ直接ダメージを与えない。弾道の表示も接触位置までにする。機銃の即時命中方式と速度・威力・発射間隔は維持する。

レーザー・ミサイルなどの飛翔弾も、発射者以外の機体との接触をIFFに関係なく判定する。発射側と同じIFFの機体を通り抜けて奥のプレイヤーへ当てる処理を廃止した。判定はフレーム間の移動区間で最も手前の接触先を使い、地形・機体へ接触した弾を消す。弾道が低い残骸の上を越える場合や、機体の脚の間など実際の命中領域に当たらない場合は通過できる。通常機体の破壊後は、従来どおり残骸の衝突判定を残さない。

## Union Tactical HAWCの左右の発射位置（共通仕様・2026-10-24）

P2MECとTCREAPは、左右の武装ポッドから2発を同時に発射する。各弾は独立した飛翔・命中判定を持つ。照準先へ向けて発射し、機体上半身の向きに合わせて銃口位置を回転させる。残弾・エネルギー・充填・発射間隔は従来の1回の射撃単位で消費・更新する。

ミサイルは武器3のTCROCKを左、武器4のSAG5Tを右から発射する。発射位置はプレイヤー・味方・敵で共通とする。


## FIL-30の棒状レーザー（共通仕様・2026-10-24）

ユーザーの最新指定により、Union SentryのFIL-30はRAIDと同じ細長い赤いレーザーとして射出する。菱形にはせず、進行方向に沿う棒状の外周と細い芯を描き、カメラへ正対させない。P2MEC・CETIの菱形、TCREAPの赤い線状弾とは分ける。プレイヤー・味方・敵で同じ描画を使う。

FIL-30はコックピット下の左右二門から同時に射出する。速度72m/s、威力、射程、充填、消費エネルギーと発射間隔は1回の射撃単位で維持する。RAIDの速度60m/sへそろえる変更は行わない。武器名に砲門数の「×2」は付けず、FIL-30と表示する。


## Scorpの二丁レーザーとマシンガンの弾道（確定仕様・2026-10-24）

- Scorp SentryのCETIは緑色のレーザーを左右の銃口から同時に2発射出する。
- Scorp Tactical Defense HAWCのRAIDは二丁。コックピット下の左右の機銃から赤い細長いレーザーを同時に射出する。モデルと射撃処理で銃口位置を共有する。銃口間隔1.1mと高さなどの寸法は試作値。
- 二丁レーザーはプレイヤー・敵・味方で共通。各弾が独立して飛翔・衝突し、エネルギー・充填・発射間隔は1回の射撃単位で更新する。既存の武器スロットと射撃キーを維持する。
- 装備表示は兵装名だけとし、搭載数を示す「×2」は表示しない。
- FLECH・DASY・zWASPの弾道は、銃口から実際の着弾点まで赤く発光する点線で描く。機内視点と外部視点で同じ表示を使い、命中した遮蔽物の先へ伸ばさない。点線の幅0.07m・表示時間0.16秒は視認性調整用の試作値。弾数・連射間隔・威力・射程は維持する。
- TCREAPも赤く発光する点線で描く。飛翔弾に追従させ、既存の弾速と衝突判定を維持する。


## サブマシンガンの二丁装備（確定仕様・2026-10-24）

Airborne Insurgency Platformを除き、サブマシンガンは原則として左右二丁装備する。現行の機体では、武器1回の操作で左右から同時に射撃する。弾薬・連射間隔は操作1回分を消費し、各弾は独立して命中判定を行う。二丁の表示位置と実際の射出位置を機体モデル・HUD・プレイヤー射撃・AI射撃で一致させる。威力・射程・弾速は変えない。

Scorp ASVのzWASPは既存の二つの装備スロットが左右それぞれの銃を表すため、各スロットからは対応する片側だけを発射する。機体別の二丁数は`weaponMountCount`で管理する。
