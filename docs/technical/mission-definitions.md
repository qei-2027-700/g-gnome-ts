# ミッションの追加と共通仕様

- 作品：G-Nome再現
- 媒体：PC向けブラウザゲーム
- 対象：ミッション定義、機体・武器の共通仕様、任務限定の例外
- 状態：1-1を任務定義として登録済み。別任務の定義を使う自動テストで共通仕様と例外の分離を確認
- 関連：[1-1の起動と実装範囲](playable-1-1.md)、[機体・武器の調査](../reference/vehicles-and-weapons.md)

## 保存先と読み込み

任務定義は `src/game/content/missions/` に置く。共通形式は [types.ts](../../src/game/content/missions/types.ts)、任務一覧は [index.ts](../../src/game/content/missions/index.ts)、1-1は [mission-1-1.ts](../../src/game/content/missions/mission-1-1.ts) を参照する。

新しい任務の定義を追加し、一覧へ登録する。登録が2件以上になると開始画面に任務選択欄が表示される。現在は1-1、Merc Tactical Defenseで雪原を移動する2-4、ミーゾンタワー防衛の2-6、3-3を登録している。2-4の原作目標は未確認で、任務完了判定を無効にしている。

任務は初期位置、配置機体、初期IFFと勢力コード、地形、岩、ウェイポイント、達成条件、説明文と結果文を持つ。シミュレーション、描画、HUD、地図、再挑戦は選択した任務定義を使う。現在の達成条件は指定地点への到達、指定機体の排除、指定武器の命中による誘引、指定勢力の機体への仲間の搭乗に対応する。護衛・施設占領・会話などが必要な任務では、その条件と処理を追加する。

`startMountedUnitId` があれば、その機体へ搭乗した状態で開始する。指定がなければ1-1と同じ徒歩開始を維持する。確認用の任務では `completionEnabled: false` を指定し、目標を達成しても任務完了にしない設定を使える。3-3はユーザー指定の搭乗条件で任務完了判定を有効にしている。誘引は `lures` に対象ID・武器・必要命中数を指定する。

地形の `biome` は `desert`（砂地）または `grassland`（草地）、`snow`（雪原）。未指定時は従来の砂地を使う。3-3はユーザー指定に基づく草地、1-1は砂地とし、地面・周辺の描画と光の反射色を任務切り替え時に更新する。機体性能・配置・当たり判定を色の違いで変更しない。

旧 `content/mission-1-1.ts` は既存テスト向けの互換参照であり、任務内容を複製しない。

### ミッションを追加するときの境界

20件程度の任務は、引き続き1任務1定義ファイルで管理する。任務固有の開始画面のタイトル・説明項目・項目別の詳細・画像領域は、任意の`briefingPresentation`へ指定する。3-3の表示データは`mission-3-3-briefing.ts`へ分けた。未指定の任務は目標の文言、機体ホログラム、実際の配置から描く地図を使う。共通の`presentation/mission-briefing.ts`へ任務IDの分岐や個別の説明文を追加しない。開始画面の表示項目と実際の達成条件は別のデータとして扱う。

任務一覧の読み込み時に`validate.ts`で全定義を検査する。任務・機体・人物・目標・地雷などのID重複、配置されていない搭乗先や攻撃対象、存在しないウェイポイント・通信話者、仲間と初期機体の人物IDの不一致を検出する。目標未確認の任務は`completionEnabled: false`を明示する。定義の型と参照検査は実プレイでの到達可能性や攻略の成立までは保証しない。

`npm test`は`tools/run-tests.mjs`で`src/`以下の`.test.ts`を再帰的に収集する。任務の検査は定義と同じディレクトリに置き、今後階層を増やしても実行対象から漏れないようにする。

ゲームが読み込む画像は`assets/cockpits/`と`assets/ui/`へ置き、音声は既存の`assets/audio/`を使う。原作画像と観察記録は引き続き`docs/reference/`へ置く。使用中の素材と元資料の対応は[素材の説明](../../assets/README.md)を参照する。

## 機体と武器の共通仕様

[vehicles.ts](../../src/game/content/vehicles.ts) を機種ごとの標準仕様、[weapons.ts](../../src/game/content/weapons.ts) を武器の共通仕様とする。機体の形状は [vehicle-shapes.ts](../../src/game/content/vehicle-shapes.ts) に置く。

例外がない任務では同じ機種の速度、シールド、装甲、エネルギー、標準装備、初期弾数、AIの機種別設定を再利用する。難易度ごとの攻撃威力や最高速度の倍率は加えない。

解決済みの機体仕様を各機体の `spec` に持たせる。移動、旋回、回復上限、損傷計算、当たり判定の高さ、3D表示、HUDと音声案内は同じ仕様を参照する。武器の性能も任務ごとに解決し、プレイヤーと敵AIが同じ定義を使用する。

弾数は武器ごとに保持する。Union SentryのFLECHは試作の400発、Merc SentryのCHUMは標準仕様資料の25発を使う。Merc Tactical DefenseのDASY・SAG5Tは以前の試作値400発をそれぞれ保持しており、原作の装弾数は引き続き照合が必要。乗降で弾薬を補充しない。

## 任務限定の例外

適用順序は「機種の標準仕様 → 任務の `vehicleOverrides` → 配置ごとの `overrides`」。武器の例外は任務の `weaponOverrides` に記す。例外のない項目は共通値を使う。

```ts
vehicleOverrides: {
  'union-sentry': { speed: 60 },
},
weaponOverrides: {
  lasers: { 'FIL-30': { damage: 8 } },
},
```

この数値は記法の例であり、1-1には適用していない。装備を変更する場合は、搭載する武器と必要な初期弾数を併せて指定する。

定義を任務・機体ごとに複製して使うため、例外や戦闘中の変化を共通定義へ書き戻さない。再挑戦は同じ任務定義で新しいシミュレーションを作り、例外指定を維持したまま弾薬・損傷・到達状況を初期化する。任務間で戦闘中の状態を持ち越す機能は別途扱う。

## 今回の戦闘調整

レーザーの発射間隔は、Union Sentryの連射が速すぎるというユーザーの指摘を受け、FIL-30を0.55秒から1秒へ変更した。RAIDの発射間隔は0.7秒を維持する。飛翔速度の最新値は[武器仕様](../gameplay/weapons-and-missile-camera.md)を参照する。FIL-30の停止時充填時間0.55秒、射程、威力は維持し、発射間隔だけを遅くした。1秒という値は操作感を確認するための仮設定で、原作での実測値ではない。即時命中を廃止し、飛翔後の衝突時にダメージを与える。移動による回避、地形・機体による遮蔽、歩兵への命中、充填率に応じた到達距離を判定する。

ミサイルの速度はCHUMを85から94m/s、SAG5Tを100から110m/sへ上げた。寿命を調整し、最大到達距離は従来の425m・600mを維持する。これらはユーザー指定による試作の調整値であり、原作で実測した値ではない。

歩兵の通常銃PRIF44は対機体ダメージを1発0.2にし、プレイヤーと敵歩兵で共通化した。対人ダメージは7。機体の下向き照準を広げ、右ドラッグの上下操作と上下キーで近くの歩兵を狙える。手動照準では機体への自動追尾を解除する。敵歩兵のGASHR所持・使用は今回の変更対象に含めていない。

## 基地・地雷原の配置

任務には任意の`base`と`minefields`を定義できる。建物の座標と寸法、地雷エリアの範囲、個々の地雷ID・位置・作動半径をデータとして保持する。爆発済みの状態はSimulationごとに生成し、任務定義へ書き戻さない。機種共通の地雷探知距離はVehicleSpecの`mineDetectorRange`で管理する。地雷原の色と基地の形は描画側、接触・遮蔽・被害はシミュレーション側へ分ける。

3-3のロケットタワーは独立した`scorp-rocket-tower`として登録し、据え置きの`category: 'tower'`を持つ。無人のScorp HAWCを別勢力の機体の名前変更で代用せず、共通の`scorp-sentry`・`scorp-tactical`を使う。配置数や座標を共通エンジンへ埋め込まない。具体的な現在値と出典は[3-3の任務仕様](../missions/mission-3-3.md#ul-urit基地と赤い地雷原2026-10-24)を参照。


仲間の搭乗条件は`objectives`の`type: 'board-faction'`へ`personIds`と`faction`を指定する。対象は現在生存している機体の操縦者で、人物IDを基準に集計する。機体の勢力は`spec.faction`で判別し、鹵獲後のIFFと区別する。判定に任務IDや基地機体IDを埋め込まない。3-3では3人全員のScorp機搭乗を必須目標とし、VISOMの誘引は`lures`で独立して管理する。


任務の初期視点は`initialView`で指定する。省略時は一人称、`external-rear`は後方、`external-diagonal`は斜め外部視点。`rearCamera`は搭乗中の後方視点の距離・高さ・注視位置を指定する。描画の生成時と`reset`で同じ初期視点を適用し、再挑戦でも前回の視点を持ち越さない。搭乗開始時はユーザーの最新指定により機内視点を優先する。詳細は[カメラ仕様](../gameplay/cameras-and-cockpits.md)を参照する。


2-4は[任務仕様](../missions/mission-2-4.md)の提供画像に合わせ、Merc Tactical Defenseへ搭乗して開始する。`snow`は白い平地と積雪した岩肌を描く。右側の岩壁は既存の`cliffs`による障害物判定を使い、雪の見た目による速度・威力の補正は加えない。装備3枠と画像の残弾は2-4の`vehicleOverrides`へ置き、共通機体の値を維持する。


## 搭乗をきっかけにした追従指示

任意の`autoFollowOnBoard`へ機種IDの配列を指定すると、主人公が該当機種へ搭乗した時点で味方へ主人公追従を指示する。3-3は`['scorp-asv']`を指定する。共通処理に任務IDを埋め込まず、目標選択を保持したまま主人公を追従先にする。搭乗時の1回だけ発行し、後続の手動命令は通常どおり扱う。具体的な対象と除外条件は[3-3の任務仕様](../missions/mission-3-3.md)を参照する。

地雷原の接近案内は`minefields[].warningRange`（外周からの距離）と`warningVehicle`（案内を出す搭乗機種）で指定する。指定機種の操縦中・同乗中だけを対象とし、任務ごと・地雷原ごとに一回性を管理する。3-3ではUnion ASV、距離60mを試作値として使う。

`lures[].onFootResponse: 'ram-player'`は、誘い出し成立後、プレイヤーが徒歩状態の場合の行動指定。対象のScorp ASVはプレイヤーへの射撃を止め、通常の射撃用停止距離を越えて接触まで追う。搭乗中は通常の戦闘処理へ戻る。3-3の対象機だけに設定し、共通のScorp ASVの性能定義は変更しない。


`bgm.start`は曲IDと進行時間での待機秒数、`bgm.afterBoard`はプレイヤーが操縦者として搭乗する対象機IDと切り替え先の曲IDを持つ。1-1では開始時に待機なしで`bgm-mission-1-1-start`を再生する。3-3では開始3秒後に`bgm-mission-3-3`、対象機`scorp-asv`への搭乗後に`bgm-union-march`を使う。ミッションの進行条件と音源ファイルのURLを分け、後者は`content/music.ts`で管理する。BGM未指定の任務で、この自動選曲を行わない。

`bgm.afterEliminate`は対象機IDの配列`unitIds`と切り替え先`trackId`を持つ。全対象の撃破を確認した後、一度だけ曲を切り替える。`Simulation.missionMusicUnits`から機体の生存と任務側の撃破状態を渡し、搭乗兵が死亡した無人機も判定に含める。未確認の機体IDを破壊済みとして扱わず、空配列・重複・配置にないIDは検証で拒否する。プレイヤー自身の機体や味方を勢力名だけで数えず、任務が指定した敵の一覧を使う。一時停止中は判定と再生を保留し、再開後に切り替える。再出撃で判定を初期化する。音源が未配置なら現在曲を続け、通知する。手動選曲中は自動切り替えを行わない。

## 施設への進入とシールドジェネレーター（2026-10-24）

機種名で搭乗可否を個別に決めず、無人・生存・進入禁止指定・ジェネレーターによる保護を共通判定する。通常の機体・ロケットタワーは`spec.boardable`未指定なら搭乗可能。`category: 'tower'`は固定設備の描画・移動区分であり、搭乗禁止を意味しない。

基地建物の`kind`は`command`・`mine-control`・`shield-generator`・`sweep-turret`を扱う。建物も既定で進入可能とし、`sweep-turret`は常に禁止する。`pilot`で占有、`health`で耐久値、`boardable: false`で進入禁止を指定できる。基地の所属は`base.faction`で管理し、省略時はScorpとする。

稼働中の`shield-generator`があれば、同じ所属軍の敵施設・ロケットタワーへの進入を禁止する。施設の所属と主人公の所属軍で判定し、IFFの書き換えでは保護を解除しない。複数あればすべての破壊が必要。機体のシールド残量とジェネレーターの保護は別の状態である。任務ID・対象施設IDを共通処理へ埋め込まない。

建物の耐久値は未指定時200という試作値。銃弾・レーザー・ミサイルの直接命中で減少し、破壊したジェネレーターの保護を解除する。破壊建物は進入・遮蔽・衝突の対象から外す。描画とシミュレーションは同じ施設IDの状態を使う。新しい施設種別の外観・性能・原作の操作画面は照合中で、任務への配置は任務定義で行う。


## 防衛目標・時間差進軍・給電

2-6の[任務仕様](../missions/mission-2-6.md)では、`objectives`の`type: 'defend'`に防衛対象の`targetIds`と排除対象の`attackerIds`を指定する。防衛対象が破壊されると失敗し、生存したまま指定部隊を排除すると成功する。耐久率と排除数は同じ任務状態から表示する。成功判定より防衛対象の喪失判定を先に行う。

`assaults`は攻撃機ID・攻撃先ID・進軍開始時刻を持つ。開始時刻までは待機し、その後は指定対象へ進軍して通常武器で攻撃する。プレイヤーから攻撃された場合は既存の報復行動を使う。共通AIへ任務IDを埋め込まない。現在の時間差進軍は初期配置の機体を動かす方式で、新しい機体の出現ではない。

施設の`kind`へ`citadel`と`power-plant`を追加し、任意の`name`で表示名を指定できる。配置機体の`powerSourceId`は電力施設を参照し、給電元の破壊で射撃・充填・回復を停止する。給電指定のない既存機体・任務は従来どおり動く。任務登録時に防衛対象・攻撃先・電力施設への参照と開始時刻を検査する。

ミーゾン・ガードタワーは共通機種定義の`powerSupply: 'external'`を使い、給電中は弾数・蓄積エネルギーの制限なく射撃できる。プレイヤー・味方・敵で同じ条件を適用し、GAUS30自体の通常の消費値は変更しない。電力プラントを配置する任務では`powerSourceId`で接続し、破壊時に停止する。2-6も電力プラントを配置し、2基の塔を`merc-power-plant`へ接続する。[共通仕様の正本](../reference/vehicles/merc-meson-tower/README.md#射撃と給電の共通仕様2026-10-29)を参照。


2-6の人物初期状態は`personnel`で配置し、`facilityId`を持つ人物は施設内として描画・攻撃対象から外す。`boardingTargetId`があれば既存の予約・徒歩移動・搭乗処理へ接続する。通信の`companions`は機体または施設を参照し、施設内の人物は作業中と表示する。

`pickups`へ人物・退出施設・排除対象・必要撃破数を指定すると、条件成立後に人物が施設から出て、主人公の操縦する機体へ同乗しようとする。経路と座席の空きを確認し、乗り換え後は新しい機体へ向かう。`type: 'board-player'`の目標は、対象人物が主人公の機体へ実際に同乗したときに達成する。

防衛目標の任意の`requiredKills`は必要排除数を持つ。達成後の防衛状態を保持し、後続の回収目標と区別する。共通処理へ人物名・要塞ID・撃破数を埋め込まない。Merc AIPの`category: 'hovercraft'`と`hoverHeight`は低空浮遊を示し、地形の当たり判定は通常の移動と共有する。上下動は小さな表示上の揺れとし、高さ3.7mという原作の機体寸法を変更しない。


## 搭乗通信と歩兵の時間差出現（2026-10-29）

`radioTriggers`の`event: 'board'`は、指定した機種の操縦者として主人公が搭乗したときに一度だけ発生する。既存の基地接近通信は`event`の省略または`'near-base'`で指定し、`range`を使う。話者の生存確認と発生済みIDはシミュレーションで管理し、音声の待ち行列は表示層で管理する。

`infantrySorties`はID・出現元施設ID・接近を判定する機種・基地からの距離・人数・初回待機時間・出現間隔を持つ。接近が成立すると進行時間で出現を予約し、施設の外へ一人ずつ配置する。兵士の勢力とIFFは出現元施設から引き継ぎ、通常の歩兵AI・射撃・被弾・描画を使う。施設の破壊後は新たな兵士を出さない。参照先と人数・距離・待機時間・間隔は任務検証で確認する。

3-3は司令部からScorp歩兵を出現させる。配置・時機の仮値は[任務仕様](../missions/mission-3-3.md#シェリダンの搭乗基地接近通信と歩兵2026-10-29)へ記録する。

## 塔への搭乗・現地守備隊・夕焼け（4-2で追加）

`board-unit`目標は`unitId`へのプレイヤーの搭乗実績を保持する。降機しても達成を保ち、再出撃で初期化する。`garrison`に配置済み機体IDを指定すると、同行人物とは独立した守備隊として共通の味方AIで迎撃する。同行者と守備隊に同じ機体が含まれても重複更新しない。参照IDは任務検証で確認する。

地形の`biome: 'grassland'`と`skyPalette: 'amber'`を組み合わせ、4-2の草原と夕焼けを表す。任務IDで描画を分岐せず、既存の3-3の空は維持する。

### 橋の操作と完了条件

`raise-bridge`は橋のIDを指定する目標。橋制御棟の`bridgeId`と地形の`river.bridgeId`を照合し、内部のスイッチから操作する。`defend.untilBridgeId`を指定した防衛目標は、その橋を上げるまで対象施設の生存を要求する。`optional: true`の目標はクリアを妨げない。操作時は橋上の機体・搭乗者・歩兵に破壊・死亡処理を適用してから、即座に勝敗を判定する。


## 川と橋の移動境界

`terrain.river`の水面は地上移動を止める。通常は橋の幅だけ通行可能にし、対応する橋IDが`raisedBridges`に入ると水面全体を通行不可にする。歩兵と地上機の衝突・経路探索へ共通の境界を渡す。AIPの機種だけは水面の境界を除外する。視線と弾道は従来の地形・建物を参照し、水面を遮蔽物にしない。
